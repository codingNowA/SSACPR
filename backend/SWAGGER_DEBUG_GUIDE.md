# Swagger 调试指南 - 交互式AI面试

## 🚀 启动服务

```bash
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

启动后访问：**http://localhost:8000/docs**

---

## 📋 完整调试流程

### 步骤 1：开始面试会话

在 Swagger 中找到：**POST /api/v1/interactive-interview/start**

点击 "Try it out"，输入以下内容：

```json
{
  "job_title": "Python后端开发工程师",
  "initial_question": "请介绍一下你对Python多线程和多进程的理解，以及它们的适用场景",
  "candidate_name": "张三"
}
```

点击 **Execute**，你会得到类似响应：

```json
{
  "success": true,
  "session_id": "interview_20260715110559_2a61633b",
  "interviewer_message": "你好张三！欢迎参加Python后端开发工程师的技术面试。\n\n我会问你一些技术问题，请你自由地阐述你的理解和经验。特别是如果你提到相关项目经验，我会很感兴趣地深入了解。准备好了吗？\n\n**第一个问题**：请介绍一下你对Python多线程和多进程的理解，以及它们的适用场景",
  "question_number": 1,
  "response_type": "question"
}
```

**⚠️ 重要：复制 `session_id`，后续所有对话都需要用到！**

---

### 步骤 2：候选人回答（浅层回答）

使用：**POST /api/v1/interactive-interview/continue**

点击 "Try it out"，输入：

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "candidate_answer": "多线程适合IO密集型任务，多进程适合CPU密集型任务。Python有GIL全局解释器锁。"
}
```

**AI 预期反应**：会追问细节，例如：
- "能详细说说为什么IO密集型任务适合多线程吗？"
- "你能举例说明什么是IO密集型任务吗？"
- "GIL是如何影响多线程性能的？"

---

### 步骤 3：候选人回答（提到项目经验）

继续使用：**POST /api/v1/interactive-interview/continue**

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "candidate_answer": "因为IO密集型任务大部分时间在等待IO操作，线程切换开销小。我在之前的电商项目中使用过多线程来处理订单数据的批量导入。"
}
```

**AI 预期反应**：会深挖项目细节（`response_type: "project_deep_dive"`）：
- "能详细说说这个电商项目的订单导入功能吗？"
- "你们的订单数据规模有多大？"
- "你具体负责哪个模块？"
- "使用多线程遇到过什么问题吗？"

---

### 步骤 4：候选人详细描述项目

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "candidate_answer": "这个项目是一个日均10万订单的电商平台。我负责开发批量导入功能，使用ThreadPoolExecutor创建了20个工作线程，从Redis队列中读取待处理订单，然后写入MySQL数据库。最初遇到了数据库连接池耗尽的问题，后来调整了连接池大小和线程数解决了。"
}
```

**AI 预期反应**：继续深挖技术细节：
- "为什么选择20个线程？有做过性能测试吗？"
- "数据库连接池具体是怎么配置的？"
- "除了连接池问题，还遇到过其他挑战吗？"
- "这个功能上线后效果如何？"

---

### 步骤 5：候选人补充技术细节

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "candidate_answer": "我们做过性能测试，20个线程时吞吐量最高，再增加线程反而因为上下文切换导致性能下降。连接池从初始的10调整到50，max_overflow设为10。上线后导入速度从原来的每分钟500条提升到2000条，性能提升了4倍。"
}
```

**AI 预期反应**：询问是否还有补充（`response_type: "ask_for_more"`）：
- "还有其他想补充的吗？"
- "在这个项目中还有什么收获？"

---

### 步骤 6：候选人表示完成

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "candidate_answer": "没有了，我觉得这个问题回答得差不多了。"
}
```

**AI 预期反应**：给出评价（`response_type: "evaluation"`）：

```
## 本题回答总结
候选人对多线程和多进程有较好的理论理解，并能结合实际项目经验说明。

## 优点
1. 能清晰区分多线程和多进程的适用场景
2. 有实际项目经验，并能详细描述技术方案
3. 遇到问题能分析并解决，展现了问题解决能力

## 不足
1. 对GIL的影响可以展开更详细的说明
2. 可以补充多进程的实际应用场景

## 改进建议
1. 深入学习CPython GIL的实现机制
2. 尝试使用multiprocessing处理CPU密集型任务

## 评分：78/100
```

---

### 步骤 7：切换到下一个问题（可选）

使用：**POST /api/v1/interactive-interview/next-question**

```json
{
  "session_id": "interview_20260715110559_2a61633b",
  "next_question": "请介绍一下你对RESTful API设计的理解，以及如何保证API的安全性"
}
```

AI 会自然过渡到下一个问题，并继续保持之前的对话上下文。

---

### 步骤 8：结束面试并生成总结

使用：**POST /api/v1/interactive-interview/end**

```json
{
  "session_id": "interview_20260715110559_2a61633b"
}
```

**AI 会生成完整的面试评估报告**：

```markdown
## 整体评价
良好

## 总体得分
78/100

## 各问题表现总结
第1题（多线程/多进程）：回答完整，有项目经验支撑，得分78分

## 优点
- 理论基础扎实，能清晰表述核心概念
- 有实际项目经验，技术方案合理
- 问题解决能力强，能分析性能瓶颈并优化
- 表达清晰，逻辑性强

## 不足
- 对某些深层次原理（如GIL机制）理解有待加深
- 多进程使用场景缺乏实际案例

## 改进建议
- 深入学习Python并发编程的底层实现
- 积累更多不同场景下的并发编程经验
- 补充分布式系统相关知识

## 录用建议
推荐录用。候选人技术基础扎实，有实际项目经验，学习能力强。建议安排进入下一轮技术面试。
```

## 🔍 查看会话信息（调试用）

使用：**GET /api/v1/interactive-interview/session/{session_id}**

替换 `{session_id}` 为你的会话ID，可以查看：
- 完整对话历史
- 当前面试状态
- 问题数量
- 对话轮次

---

## 🗑️ 删除会话（清理用）

使用：**DELETE /api/v1/interactive-interview/session/{session_id}**

## 💡 调试技巧

1. **观察 `response_type` 字段**：
   - `question` - 新问题
   - `follow_up` - 追问细节
   - `project_deep_dive` - 深挖项目
   - `ask_for_more` - 询问补充
   - `evaluation` - 评价打分

2. **测试不同回答风格**：
   - 简短回答 → AI会追问
   - 提到项目 → AI会深挖
   - 详细回答 → AI会询问补充
   - 说"完了" → AI会评价

3. **保存 session_id**：
   每次对话都需要使用同一个 session_id，这样AI才能记住之前的对话

4. **观察对话上下文**：
   AI会记住你之前说过的所有内容，后续追问会基于前面的对话

## 🎓 课程要求验证

通过 Swagger 调试可以验证以下 LangChain 功能：

✅ **对话记忆**：AI记住之前所有对话  
✅ **智能追问**：根据回答内容自动追问  
✅ **项目深挖**：识别项目经验并深入询问  
✅ **类型识别**：自动识别回答是否完整  
✅ **流式输出**：启用 streaming=True（需前端配合显示）
