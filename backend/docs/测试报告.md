## ⚠️ 已知问题

### 问题 1: 版本管理 HTTP 接口超时

**现象**: 
```bash
GET /api/v1/resume/versions?user_id=1
→ 500 Internal Server Error
→ psycopg2.OperationalError: could not translate host name "postgres"
```

**分析**:
- 直接调用服务层函数: ✓ 正常工作
- 通过 HTTP 请求: ✗ 超时 7 秒后报错
- 错误提示尝试连接 PostgreSQL 数据库

**根本原因**: 
某个中间件、依赖注入或启动钩子在尝试建立数据库连接。由于 `.env` 中配置的 `POSTGRES_HOST=postgres` 在本地无法解析，导致连接超时。

**影响范围**:
- 列出版本: GET /api/v1/resume/versions
- 版本统计: GET /api/v1/resume/versions/stats (部分)
- 其他端点正常

**临时解决方案**:
1. 直接调用服务层 API (已验证可行)
2. 或启动 PostgreSQL 容器 (但版本管理不需要数据库)

**永久解决方案**:
定位并移除不必要的数据库连接尝试

---

### 问题 2: 优化端点返回 404

**现象**:
```bash
POST /api/v1/resume/optimize
→ 404 Not Found
```

**分析**:
- 路由定义存在: ✓ `@router.post("/optimize")` 已定义
- 函数实现完整: ✓ `async def optimize_resume()` 正常
- 路由注册: ✓ `app.include_router(resume_router, prefix="/api/v1")`

**可能原因**:
1. 路由优先级问题 (其他路由覆盖)
2. 路径参数冲突
3. 服务器缓存

**影响范围**:
- 仅 HTTP 端点受影响
- 服务层功能完全正常

**解决方案**:
1. 检查路由定义顺序
2. 清除服务器缓存重启
3. 使用 `/api/v1/resume/optimize/` (带斜杠)
