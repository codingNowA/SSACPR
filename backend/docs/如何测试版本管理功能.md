# 如何测试简历版本管理功能

## 功能说明

简历版本管理功能支持：

1. **版本创建**：保存简历并自动解析、评分、优化
2. **版本列表**：查看所有简历版本
3. **版本详情**：查看某个版本的完整信息
4. **版本更新**：修改版本标题、描述、目标岗位
5. **版本删除**：删除不需要的版本
6. **版本激活**：设置当前使用的版本
7. **版本对比**：对比两个版本的差异
8. **版本统计**：查看版本数量、评分趋势等

## 方法 2：使用 curl 命令

## 方法 3：使用 Python 脚本

```python
import requests

BASE_URL = "http://localhost:8000/api/v1/resume"

# 1. 创建版本
files = {'file': open('resume.pdf', 'rb')}
params = {
    'title': '初始版本',
    'description': '第一版简历',
    'target_job': 'Python 后端工程师',
    'set_as_active': True,
    'auto_process': True
}
response = requests.post(f"{BASE_URL}/versions", files=files, params=params)
print("创建版本:", response.json())
version_id = response.json()['data']['version']['id']

# 2. 获取版本列表
response = requests.get(f"{BASE_URL}/versions")
print("版本列表:", response.json())

# 3. 获取版本详情
response = requests.get(f"{BASE_URL}/versions/{version_id}")
print("版本详情:", response.json())

# 4. 更新版本
update_data = {
    'title': '优化后的版本',
    'description': '增加了量化数据'
}
response = requests.put(f"{BASE_URL}/versions/{version_id}", json=update_data)
print("更新版本:", response.json())

# 5. 版本统计
response = requests.get(f"{BASE_URL}/versions/stats")
print("版本统计:", response.json())
```

## 存储结构

版本数据存储在：`uploads/resumes/versions/{user_id}/`

```
uploads/resumes/versions/
└── 1/                          # 用户ID
    ├── metadata.json           # 元数据文件
    ├── v1.pdf                  # 版本1文件
    ├── v2.pdf                  # 版本2文件
    └── v3.docx                 # 版本3文件
```

**metadata.json 结构**：
```json
{
  "next_version": 4,
```

## 常见问题

### Q: 版本号是如何生成的？
A: 版本号自动递增，从1开始。每个用户的版本号独立。

### Q: 可以同时有多个激活版本吗？
A: 不可以，系统保证同时只有一个版本为激活状态。

### Q: 删除版本会删除文件吗？
A: 是的，删除版本会同时删除对应的文件。

### Q: auto_process=false 时会发生什么？
A: 只保存文件和基本信息，不进行解析、评分、优化。适合快速保存或手动处理的场景。

### Q: 版本对比能对比哪些内容？
A: 对比基本信息（标题、目标岗位）、评分变化（总分和各维度）、内容变化（工作经历、项目、技能数量）。

### Q: 版本数据存储在哪里？
A: 文件存储在 `uploads/resumes/versions/{user_id}/`，元数据存储在 `metadata.json`。

### Q: 支持数据库存储吗？
A: 当前版本使用文件存储，便于开发和测试。二期可以迁移到数据库（PostgreSQL）。

## 注意事项

1. **用户隔离**：不同用户的版本数据完全隔离
2. **文件管理**：删除版本会删除文件，请谨慎操作
3. **激活版本**：建议始终保持一个激活版本
4. **版本命名**：建议使用有意义的标题，便于识别
5. **定期清理**：建议定期清理不需要的旧版本
